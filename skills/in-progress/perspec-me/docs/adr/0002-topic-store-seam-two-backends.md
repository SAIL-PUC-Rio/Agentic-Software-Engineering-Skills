# A topic-store seam separates Topic operations from where Topics live

Whether a Topic lives as a Markdown file or as a Wayfinder child issue changes how it's claimed, how Blocked and the Frontier are computed, and how a resolution is recorded — but a Session, a Map update, and a Resolution page shouldn't need to know which. Writing the interview and mapping logic against one specific backend (Markdown files, say) would mean rewriting or forking that logic the day Wayfinder or another tracker becomes available, and issue #10 explicitly asks for both: use the tracker's own mechanics when Wayfinder is present, and "implement a minimal Markdown fallback that preserves the same concepts" when it isn't.

So the operations are defined once, independent of storage: create a Topic, claim a Topic, list the Frontier, wire a Blocked edge between Topics, and record a resolution (close the Topic, append its line to Decisions so far, update its Concerns' Resolution pages). A local Markdown backend implements them as topic files beside the Map file — the same local-markdown-convention fallback pattern `docs/agents/issue-tracker.md` already documents for issue trackers in general. An issue-tracker backend implements them as Wayfinder child issues of a `wayfinder:map`, reusing the exact mechanics `docs/agents/issue-tracker.md` already defines for Wayfinder — native issue dependencies for Blocked, `gh issue edit --add-assignee @me` for claim, the map's open-children-minus-blockers-minus-assignee query for Frontier, a comment-then-close for resolution — rather than inventing parallel ones.

Consequences: every other perspec-me ticket (the session procedure, the map-construction logic, the Wayfinder-resolver integration) writes against the five operations, never against a `gh issue ...` call or a Markdown file path directly; a ticket that reaches past the seam to touch a backend's storage detail is out of scope for anything but the two backend tickets themselves. Adding a third backend later (e.g. Linear) means implementing the same five operations, not touching Session or Map logic. It also means the seam's operation names — not either backend's own vocabulary — are what later ADRs, the `SKILL.md`, and this `CONTEXT.md` should cite.
