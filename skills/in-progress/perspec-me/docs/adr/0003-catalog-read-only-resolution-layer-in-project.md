# The catalog ships inside the skill and stays read-only; a project's resolution layer lives in the consuming project

The PerSpecML catalog (`skills/in-progress/perspec-me/catalog/`) is reference material shared by every project that uses `perspec-me` — the same 60 Concerns and five Perspectives regardless of which project is being specified. The catalog's own `NOTE.md` already states it is immutable reference material for the skill and must not be edited, translated, or re-scraped during use. If a project's Map, Resolution pages, or fallback Topic files lived inside the skill folder instead, every project using `perspec-me` would write into a shared, versioned, plugin-distributed directory — collisions across unrelated projects, resolution content silently overwritten by the next skill update, and no way to tell a project's own decisions from the catalog's canonical text.

So the skill folder holds only the catalog (read-only) and the routing/session logic; each consuming project keeps its own resolution layer under `requirements/perspec-me/<map-slug>/` in that project's own repository — `MAP.md`, `perspectives/<perspective-id>.md`, `concerns/<concern-id>.md` Resolution pages, and, only when the local Markdown backend (ADR 0002) is in play, `topics/<topic-id>.md` — created on demand as a Map or Session actually produces content, never scaffolded wholesale ahead of use.

Consequences: a `perspec-me` skill update (new catalog wording, a new Concern) never touches or is touched by any project's decisions, because the two live in different repositories entirely. Any session step that would write to `skills/in-progress/perspec-me/catalog/` is a bug, not a feature; the catalog's own link-check script (`catalog/check-links.py`, from issue #12) only ever needs to run when the catalog itself changes, never as part of a project's `perspec-me` use. For the issue-tracker backend specifically, this also means `requirements/perspec-me/<map-slug>/topics/` stays unwritten — that directory exists only when the local Markdown backend is the one recording Topics.
