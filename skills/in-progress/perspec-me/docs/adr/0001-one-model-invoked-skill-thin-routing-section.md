# perspec-me is one model-invoked skill; the "command" is a thin routing section, not a separate artifact

The spec (issue #10) asks for a thin `perspec-me` command plus a base skill the command hands off to — two artifacts, one thin and one doing the interview work. This repo's `.agents/invocation.md` makes that split impossible as designed: a skill is either user-invoked (reachable only by the human typing its name) or model-invoked (reachable by model or user), and "a user-invoked skill can never be reached this way, full stop... no other skill can call it, including by naming it to the Skill tool." Wayfinder needs to call `perspec-me` as a resolver for grilling topics that declare `resolver: perspec-me` in their own frontmatter; that call only works if `perspec-me` is model-invoked. Splitting it into a user-invoked "command" in front of a model-invoked "skill" would either block Wayfinder's call (if the command is the only invoked artifact) or let Wayfinder skip the command entirely and call the skill directly (defeating the point of a thin single entry point) — and the two artifacts would drift out of sync over time regardless.

So `perspec-me` ships as one `SKILL.md`, model-invoked. Its first section is the routing logic the spec asked of the command: it interprets a bare `<seed>` (a topic, issue, idea, or path with no verb) and the verbs `resolve <topic-ref>`, `resume [session-or-map]`, `status [map]`, `review <concern-id>`, and `map <effort-or-destination>`; finds or creates the Session and, where the effort needs one, the Map; and hands off to the session procedure. The routing section only dispatches — it must not duplicate interview logic, Concern selection, or Resolution-page bookkeeping, all of which live in the session procedure it calls into.

Consequences: because `perspec-me` is reachable both by a human typing its name and by Wayfinder (or another skill) routing a resolver call to it, its `SKILL.md` description must stay tight and trigger-specific — generic phrasing ("helps structure requirements", "asks questions about a project") would over-trigger the model into invoking it on unrelated planning conversations. The description names PerSpecML, Concern, and Topic explicitly rather than describing the interview technique in the abstract. It also means there is no separate command file to keep in sync with the skill, and no risk of the routing half and the interview half disagreeing about verb handling — one file is the single source of truth for both entry points.
