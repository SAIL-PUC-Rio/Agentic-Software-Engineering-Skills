# M3 — Definition

[Table 9, p. 9, row M3 — Input & Output](../../1-s2.0-S0164121224000980-main.pdf#page=9) introduces its definitions with “Addressing this concern involves specifying”:

> the expected inputs (features) and outcomes of the model. Of course, the set of meaningful inputs can be refined/improved during pre-processing activities, such as feature selection

## When to analyze it

Analyze Input & Output when discussing [Train the ML model](../../perspectives/model/README.md#train-the-ml-model) in the [Model perspective](../../perspectives/model/). In the PerSpecML workflow, inspect the concern and its available relationships, determine whether it applies to the system, and then specify it if applicable. The task assignment identifies where to have this specification discussion; it does not require waiting until implementation.

The template excerpt marks the corresponding block with E for experimentation; its details can be refined as the project progresses. See [elicitation](elicitation.md) for the exact block and the limits of this mapping.

## Source differences

Table 9 names this concern “Input & Output”; Figure 2 uses “Inputs & outputs”. Figure 4 puts the corresponding question under “Define the inputs (features) and output (label) of the model”, whereas Figure 2 places M3 in “Train the ML model”. In M3's references, Figure 2 prints lowercase “i10”; links use the existing I10 ID with that normalization recorded.
